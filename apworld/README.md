# apworld

Python. This is not a normal apworld, and if you came here from the
Archipelago community that matters, so it is the first thing said.

**The item and location tables are not written here.** They are generated from
`gamedata/`, a Go package, and committed as JSON under `tf2_mvm/data/`. This
directory holds the code that reads that JSON and the logic that cannot be
expressed as data. The reasoning is in [ADR
0001](../docs/adr/0001-go-owns-the-game-data.md).

## What is here

`tf2_mvm/`, the apworld package:

- `__init__.py` — the `World` subclass. Draws the missions, builds the regions
  and the item pool, sets the access rules and the goal, fills the slot data.
- `data.py` — reads the generated JSON and refuses a format version it does
  not know. Uses `pkgutil.get_data`, not `open`: a packaged `.apworld` is a
  zip and there is no file to open.
- `options.py` — the YAML options. **Hand-written, not generated.** Option
  classes are code with docstrings that the Archipelago website renders as
  player-facing documentation, so they are not a table. Where an option
  enumerates something the Go side owns, the enumeration is checked against the
  export at import rather than trusted.
- `rules.py` — what a mission asks for before its waves count as beatable. The
  numbers climb with the difficulty tier, which is what gives a seed spheres
  instead of one flat list of tickets.
- `data/*.json` — generated by `gamedata/`, committed. Do not hand-edit. CI
  fails if these differ from what the Go source produces.
- `docs/` — the setup guide and game info page Archipelago expects. The game
  info file name must be `<lang>_<game name>.md`, spaces included.
- `test/` — one class per option set. `WorldTestBase` adds fill, all-state
  reachability and the sphere 0 check to each of them for free.

## Running it

There is no Archipelago in this repo. Point a 0.6.7 checkout at this folder:

```sh
ln -s "$PWD/tf2_mvm" <archipelago>/worlds/tf2_mvm     # a folder must live in worlds/
cd <archipelago>
SKIP_REQUIREMENTS_UPDATE=1 python -m unittest discover -s worlds/tf2_mvm/test -t .
SKIP_REQUIREMENTS_UPDATE=1 python Generate.py --player_files_path Players
```

`custom_worlds/` takes `.apworld` zips only; a folder dropped there is found
and then fails to import. Build the zip with
`python Launcher.py "Build APWorlds" -- "Team Fortress 2 Mann vs Machine"`,
which writes `build/apworlds/tf2_mvm.apworld` and stamps the manifest.

## The data contract

The exported JSON carries a format version. The apworld refuses to load a data
file whose version it does not recognise, rather than half-loading it and
generating a broken seed.

The game name string and the AP base id offset also come from the export.
They are not repeated here. ALPHAMARIOX's fork declares two different game
names in two files, which is exactly the failure this avoids.

## Building the `.apworld`

The build zips `tf2_mvm/` with the committed `data/` inside it, minus whatever
`.apignore` excludes. That is why `data/` is committed rather than gitignored:
the result is a standalone artifact that works on a machine with no Go
toolchain.

## Upstream

Submitting this to `ArchipelagoMW/Archipelago` is explicitly out of scope for
v1 (`docs/spec.md`). A JSON-reading apworld may not be accepted as-is. Revisit
once it generates and has been played end to end.
